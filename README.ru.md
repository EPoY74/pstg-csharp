# PSTG — Pump Station Telemetry Gateway

[English version](./README.md)

PSTG — это **industrial telemetry gateway** и **monitoring backend** для насосных станций, разрабатываемый на **C# / .NET** с опорой на реальный контекст **PLC (programmable logic controller — программируемый логический контроллер)**, **Modbus TCP** и задач промышленной автоматизации.

Практическая цель проекта — забирать телеметрию с оборудования насосной станции, сохранять сырые данные для диагностики, нормализовать важные сигналы и подготовить чистую основу для мониторинга, анализа, трендов, тревог, API, дашбордов и будущего графического интерфейса. Этот проект это  **industrial telemetry gateway и monitoring backend для насосных станций с понятным путём развития в сторону облегчённой SCADA-like / HMI-like системы мониторинга**

---

## Зачем нужен этот проект

Во многих промышленных системах телеметрия существует, но использовать её в прикладном ПО неудобно:

- данные в ПЛК есть, но инженер всё равно зависит от ручных проверок или вендорских инструментов;
- сырые регистры Modbus неудобны для прямой работы на уровне backend-кода;
- мониторинг, диагностика и хранение часто смешаны в один слой;
- свежесть данных, качество сигнала и трассируемость редко моделируются явно;
- OT/IT-интеграция часто начинается как разовый скрипт, а не как сопровождаемая система.

PSTG нужен, чтобы решить это аккуратно и инженерно.

---

## Что такое PSTG

PSTG задуман как база для:

- **сбора промышленной телеметрии** с ПЛК и полевых устройств;
- **мониторинга насосных станций** и диагностики;
- сохранения **сырых блоков регистров** для трассировки и разборов;
- описания **нормализованных сигналов** через явную метаинформацию;
- последующего добавления **тревог, трендов, журналов событий, дашбордов и web/API-слоя**;
- постепенного роста от локального инструмента мониторинга к более зрелому **industrial software / SCADA-adjacent backend**.

## Текущее состояние репозитория

Этот репозиторий отражает **переписывание PSTG на C#**.

Текущая ветка разработки сосредоточена на том, чтобы выстроить систему правильно «изнутри наружу»:

- domain-first моделирование;
- явные сущности / value objects для станций и сигналов;
- разделение domain, infrastructure, runtime и presentation-слоёв;
- worker/service-подход для polling (опроса) и фоновой обработки;
- архитектура, которую позже можно развить до хранения, API, дашбордов, тревог и UI.

Там, где реализация ещё развивается, PSTG следует воспринимать как **активный инженерный прототип** и **портфельный industrial-backend-проект**, а не как завершённый production-ready SCADA-продукт.

## Ключевые инженерные принципы

### 1. Сначала raw-данные
Сырая телеметрия важна. Для промышленной диагностики и разборов нужно уметь хранить исходные чтения, а не только уже интерпретированные значения.

### 2. Нормализованные сигналы с явной метаинформацией
Сигнал должен быть описан явно: function code, адрес регистра, количество регистров, порядок слов, тип данных, единицы измерения, а позже — и побитовая расшифровка там, где это действительно нужно.

### 3. Чёткое разделение ответственности
Проект стремится разделять:

- **Domain** — что означает станция, сигнал, результат опроса или состояние качества данных.
- **Infrastructure** — как данные читаются, повторяются, хранятся и логируются.
- **Runtime / application flow** — как оркестрируются сценарии опроса и use case-логика.
- **Presentation** — будущий API, dashboard, HMI или другой UI-слой.

### 4. Практическая расширяемость
Первое MVP может стартовать даже с простого raw-read. Но архитектура должна позволять без переписывания с нуля перейти к более богатому декодированию сигналов, хранению, тревогам, трендам, dashboard-функциям и интеграциям.

## Границы проекта

### PSTG — это
- проект по промышленной телеметрии;
- основа monitoring-backend-системы;
- программный прототип для насосной станции;
- C# / .NET-репозиторий с реальным доменным контекстом;
- база для будущих alarms, trends, dashboards и UI.

### PSTG — это не
- готовая enterprise SCADA-платформа;
- сертифицированная safety-система;
- система прямого управления safety-critical автоматикой;
- замена объектной инженерной проверки, промышленной валидации и нормативной оценки.

Это различие сделано специально.

## Техническое направление развития

Долгосрочное техническое направление включает:

- фоновые polling-service процессы;
- хранение телеметрии и метаданных;
- monitoring API;
- декодирование сигналов и побитовые маппинги там, где это уместно;
- семантику data freshness / stale-data;
- alarms и event journaling;
- dashboards и графический интерфейс;
- упаковку для практического локального развёртывания.

Именно это делает PSTG интересным не только как учебный проект, но и как компактный **industrial monitoring backend**, **telemetry platform** и потенциальную основу для небольшой **SCADA-like** системы мониторинга.
